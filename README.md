# Nozhik

Легковесная модульная IDE на Rust с нативной производительностью для Windows,
macOS и Linux. Цель проекта — инструменты для кода и баз данных уровня
PhpStorm/DataGrip с независимыми подсистемами и явными контрактами.

## Статус

**v0.1.52. Этап 9 реализован.** Пятнадцать крейтов,
нативная оболочка egui/eframe, ленивое дерево проекта, файловый I/O в фоне,
watcher, fuzzy-поиск по путям, вкладки, виртуализированный Rope-редактор
и встроенный Git-клиент. PHP: Tree-sitter подсветка, LSP-диагностика, completion,
hover и переход к определению. Встроенный PTY-терминал поддерживает локальный
шелл, ANSI-цвета, вкладки и TUI-программы. SSH: удалённый шелл, SFTP-редактор
и локальные туннели. Встроенный клиент PostgreSQL, MySQL/MariaDB и SQLite:
дерево схем, SQL-консоль и виртуализированный Data Grid. PHP-линтеры
`PHPStan`, `PHPCS`, `Psalm` и `PHPMD` запускаются кнопкой с жучком внутри
Docker-контейнера; результаты видны в Problems и в редакторе. Кнопка запуска
выполняет настроенный PHPUnit в консоли того же контейнера; вывод остаётся в
этой консоли.

## Старт приложения и версия

Иконка приложения и логотип стартового окна используют изображение `docs/img/logo.png`.

Запуск без аргумента проекта открывает компактное стартовое окно: логотип Nozhik,
текущая версия, поиск по недавним проектам, **Open Folder…**, **Clone Repository…**
и **About** со ссылкой на этот репозиторий. IDE появляется после успешного открытия
папки; несуществующий путь оставляет стартовое окно с ошибкой. Явный путь в CLI
(`cargo run -p app -- /path/to/project`) открывает указанный проект напрямую.

Клонирование: URL (включая `owner/repository`) или GitHub.com. Во вкладке URL
выберите публичный доступ/системные credentials, HTTPS-токен, логин/пароль либо
SSH-ключ и passphrase. GitHub.com связывается через personal access token:
API проверяет аккаунт и загружает доступные ему репозитории, включая приватные,
с поиском и пагинацией. Enterprise не поддерживается. GitHub не принимает пароль
аккаунта для Git: используйте токен или SSH. SSH использует стандартную проверку
host key libgit2; неизвестный/недоверенный сервер нельзя обойти в этом диалоге.

Секреты не сохраняются на диск и не включаются в remote URL. После успешного
клонирования credentials передаются открываемому проекту на текущую сессию;
диалог очищается. После повторного открытия проекта токен/пароль вводится заново
в Settings → Git либо используется системный credential helper/SSH agent. Укажите новую абсолютную папку внутри существующего родителя;
существующая папка не перезаписывается. Сеть/checkout работают в фоне, Cancel
запрашивает отмену; её завершение зависит от текущей операции транспорта.
После клонирования проект автоматически открывается в IDE.

Версия — `[workspace.package].version` в `Cargo.toml`, общая для интерфейса,
Cargo packages и macOS bundle. Текущая версия — **0.1.52**; следующая доработка/коммит
должна увеличить patch до **0.1.53** (правило закреплено в `AGENTS.md`).

## Несколько проектов

Цвет иконки проекта одинаков в стартовом окне, меню и верхнем заголовке.
Он выбирается из 12 ярких цветов по первым трём символам названия без учёта
регистра и не зависит от пути или порядка недавних проектов.

Каждая папка открывается в отдельной вкладке одного окна. Верхняя строка показывает
имя активного проекта; её меню содержит **Open…**, **Clone Repository…**, открытые
и недавние проекты. Повторное открытие той же canonical-папки переключает вкладку.
Вкладки переставляются во время горизонтального перетаскивания с удерживаемой
левой кнопкой мыши. Полосы прокрутки под ними нет: при переполнении доступны
кнопки влево/вправо, колесо мыши и горизонтальный скролл трекпада. Активная вкладка тёмная,
остальные светлеют при наведении; крестик появляется при наведении на любую вкладку.
Закрытие последнего проекта возвращает стартовое окно.

У каждого проекта независимые дерево, редактор и несохранённые буферы, терминалы,
SQL-консоли, Git, SSH и языковые workers. Переключение сохраняет их состояние;
закрытие завершает службы этого проекта. Закрытие окна проверяет также правки
неактивных проектов через Save All / Discard / Cancel.

Новый проект получает `Config::default()`, включая AI debounce **1000 мс**.
Изменения настроек автоматически сохраняются worker в `<project>/.nozhik/settings.toml`
и загружаются при повторном открытии; диалог показывает имя и полный путь проекта.
Параметры панелей сохраняются отдельно в `.nozhik/layout.json`. Глобальный
`settings.toml` и `--config` относятся к стартовому окну; настройки проектов
из них не наследуются. Повреждённые настройки проекта показывают ошибку открытия,
сохраняют существующие сессии и исходный файл. Общий список недавних проектов
остаётся в каталоге настроек приложения.

## Заметки Snippets

Кнопка Snippets стоит в верхней группе левой полосы, между Docker и HTTP Requests.
Раздел открывается как Git: слева теги и избранное, в центре список заметок и
текст. Это любые заметки, фрагменты кода и консольные команды. Они хранятся в
`snippets.json` в корне открытого проекта и не делятся между проектами. Файл
создаётся при первом открытии раздела. На заметку можно ставить много тегов;
слева они показаны строками со счётчиком. Готовую заметку можно править,
удалять и менять набор тегов.

В шапке редактора три кнопки: скопировать текст, назначить теги и открыть в
консоли. Консоль получает тот же текст: в уже открытый терминал или в новый,
если терминала нет. Вставка не нажимает Enter. Многострочный фрагмент ждёт,
пока оболочка примет безопасную вставку, и не уходит в терминал сырыми
переводами строк. Удаление — контекстное меню карточки или клавиша Delete,
когда курсор не в поле ввода.

## HTTP Requests

Кнопка HTTP Requests стоит в верхней группе левой полосы, между Snippets и Tools.
Раздел открывается как Snippets: слева библиотека и теги, в центре список и
построитель. Запросы хранятся в `http_requests.json` в корне открытого проекта
и не делятся между проектами. Файл создаётся при первом открытии раздела.
Пункт HTTP Requests есть и в меню View.

Построитель задаёт имя, метод и URL. Вкладки Query, Headers и Body принимают
пары имя/значение. Query уходит и у запроса с телом. Тело бывает пустым, JSON,
текстом, form URL encoded или multipart form-data. Снятый флажок оставляет
строку в файле, но не отправляет её и не показывает в cURL. Под построителем
окно cURL: правка построителя сразу переписывает команду, правка команды
обновляет построитель. Команда, которую не удалось разобрать, показывает
ошибку и не затирает запрос. Send и Cmd+Enter отправляют вызов. Ответ
показывает код, время, заголовки и тело.

Теги назначаются у выбранного запроса. Слева тег — строка со счётчиком.
Удаление — контекстное меню карточки или клавиша Delete, когда курсор не в
поле ввода.

Кнопка **To OpenAPI** записывает выбранный запрос в уже открытый OpenAPI JSON
или в `openapi.json` в корне проекта. В раскрытой карточке операции OpenAPI
кнопка **To HTTP Requests** переносит этот вызов обратно в раздел.

## Локальные бинарники

`binaries/` исключён из Git. По умолчанию обновляются и проверяются только
бинарники текущей платформы (на этом Mac — macOS ARM64):

```sh
python3 scripts/update-binaries.py
python3 scripts/update-binaries.py --check
```

Windows x64 собирается локально только по необходимости:

```sh
python3 scripts/update-binaries.py --target x86_64-pc-windows-gnu
python3 scripts/update-binaries.py --check --platform windows-x64
# Освободить Windows-кэш после сборки:
rm -rf target/x86_64-pc-windows-gnu
```

Для cross-build нужны MinGW-w64 и Rust target `x86_64-pc-windows-gnu`.
На Windows доступен `--target x86_64-pc-windows-msvc`.
`--check --all-platforms` явно проверяет оба комплекта; Windows-бинарник
между сборками по запросу может отставать от исходников.

macOS: `binaries/macos-arm64/nozhik` и `Nozhik.app.zip` для Finder/Dock.
Windows: `binaries/windows-x64/nozhik.exe`. Очистка target сохраняет эти файлы.
CI по-прежнему собирает обе платформы на GitHub и сохраняет временные artifacts.
Скрипт проверяет SHA-256 исходников и готовых файлов; успешная сборка не заменяет
тесты и линтинг.

## Сборка и запуск

Установите текущий stable Rust через [rustup](https://rustup.rs/).
`rust-toolchain.toml` выбирает stable с rustfmt и Clippy; используется edition 2024.
`Cargo.lock` фиксирует разрешённые зависимости приложения и хранится в Git.

Платформенные инструменты:

| Система | Требования |
| --- | --- |
| Windows | Visual Studio Build Tools, компонент Desktop development with C++, Windows SDK; Rust MSVC toolchain |
| macOS | Xcode Command Line Tools: `xcode-select --install` |
| Linux | C/C++ toolchain, pkg-config, заголовки X11/Wayland/xkbcommon; активная графическая сессия |

Git backend собирает libgit2/OpenSSL из исходников: системный Git для локальных
операций не нужен. Для сборки также необходим Perl в PATH и make на Unix;
на Windows используйте Perl с совместимым MSVC окружением.

Для Ubuntu/Debian:

```sh
sudo apt-get update
sudo apt-get install -y build-essential perl pkg-config libx11-dev libxkbcommon-dev libwayland-dev
```

Одинаковые команды в PowerShell, Terminal и Linux shell, из корня репозитория:

```sh
cargo build --workspace
cargo test --workspace --all-features
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo run -p app
cargo build --workspace --release
```

Бинарник: `target/release/app` (`app.exe` на Windows).
Закрытие окна завершает приложение и обработчик событий. Для тестов GUI
не требуется; для запуска нужен доступ к дисплею. CI проверяет три ОС;
наличие workflow само по себе не подтверждает успешный прогон.

## CSS

CSS-файлы получают Tree-sitter подсветку и локальное форматирование через
Reformat Code (весь файл либо выделение). Профиль CSS по умолчанию доступен
в Settings → File Types; он задаёт отступы и пробел после запятой.
Форматтер сохраняет токены и синтаксис; ошибочный CSS сначала нужно исправить.

Слева от строк показаны цветные квадратики для Hex, именованных цветов,
RGB/RGBA, HSL/HSLA и цветов градиентов. Клик открывает палитру с прозрачностью,
RGBA и Hex; изменение сразу правит код и поддерживает Undo.
Для однозначных переменных `var(--name)` из этого же файла показывается цвет
определения, включая цепочки ссылок; палитра меняет исходный литерал переменной.
Неоднозначные определения, внешние переменные и вычисляемые цвета не разрешаются.
Это статический просмотр, без вычисления DOM, каскада и импортов браузером.

Индекс проекта отдельно сохраняет CSS-классы, их регистр, экранированные имена,
пути и диапазоны. Изменения открытого буфера видны в памяти; на диск пишутся только
сохранённые факты (`.nozhik/cache/index_css_v6.json`).

При вводе имени CSS-свойства появляются стандартные подсказки; Tab/Enter вставляют
свойство с `: `, сохраняя существующее двоеточие. В значениях, комментариях, строках
и селекторах подсказки свойств не появляются. В статическом `class="..."` PHP/PHTML
и в CSS-селекторах предлагаются классы из CSS-индекса, включая имена с дефисами.
Замена касается текущего токена и поддерживает Undo.

Cmd+клик на macOS (Ctrl+клик на других платформах) по классу в CSS открывает
модальный список всех индексированных селекторов и PHP/PHTML-использований с файлами,
строками и preview. Клик по классу в PHP переходит к определению; при нескольких
определениях открывается выбор. В списках работают поиск, стрелки, Enter и Escape.
Для стандартных CSS-свойств такие переходы и поиск использований не включаются.

PHP-выражения, PHP-строки с HTML, комментарии и содержимое script/style не считаются
статическими class-атрибутами. Runtime-значения и HTML entities в именах классов
не вычисляются. Native HTML/JS пока не индексируются; будущие языковые extractors
могут передавать ссылки в общий каталог CSS-классов.
CSS можно отключить в Settings → Languages. В старых
проектах с сохранённым списком языков включите там CSS вручную.

## JSON и Tools

JSON-файлы получают подсветку ключей, строк, чисел и boolean/null и форматирование
через Reformat Code (весь документ или самостоятельное JSON-значение в выделении).
Профиль JSON в Settings → File Types задаёт отступы; по умолчанию — два пробела.
JSON не добавляется в семантический индекс и не запускает PHP LSP. При загрузке
старых настроек с непустым списком языков JSON включается автоматически; отключение JSON в новых настройках и пустой список языков сохраняются.

Кнопка Tools в левом меню открывает каталог в основной рабочей области IDE,
как раздел Git. Пункт JSON переключает её на полноразмерный инструмент:
Minified JSON сверху, Formatted JSON снизу. Разделитель между полями можно
перетаскивать; Back to Tools возвращает каталог. Поля имеют независимую прокрутку.
Правки синхронизируются после каждого корректного изменения; форматирование
применяется автоматически. Пока JSON незавершён или ошибочен, введённый текст
сохраняется, а второе поле показывает последний корректный результат. У каждого
поля есть Copy; работают выделение, вставка и обычные команды редактирования.
Clear очищает оба поля. Лимит инструмента — 2 MiB входного текста; разбор идёт
в фоне. Это временный инструмент проекта: его текст не сохраняется при закрытии IDE.

Open in Tools / JSON над файловым редактором переносит текущий буфер, включая
несохранённые правки, в раздел инструмента. Инструмент не записывает исходный файл.
Форматтер меняет только whitespace: сохраняет порядок и повторы ключей, escape-
последовательности и точное написание чисел. Ошибочный JSON нужно исправить до
форматирования.

## OpenAPI

Файл `openapi.json` или `swagger.json` (также `.yaml`/`.yml` и имена с суффиксом
`.openapi.` / `.swagger.`) в дереве проекта и на вкладке редактора показывается
зелёной круговой меткой OpenAPI. Обычный JSON, включая коллекции Postman,
остаётся со значком `{}`. Документ YAML получает только метку: рабочая панель
открывается для JSON.

Любой `.json`, в корне которого есть OpenAPI 3.x или Swagger 2.0, сначала
открывается как обычный JSON: подсветка, Reformat JSON и Open in Tools / JSON.
Над редактором стоит переключатель JSON | GUI. GUI не записывает файл. Выбранный
режим, сервер, черновики Try it out и введённая авторизация живут, пока документ
открыт, и не пишутся на диск. Если текст перестал быть спецификацией, переключатель
исчезает. Сломанный JSON, в котором всё ещё узнаётся спецификация, оставляет
переключатель и показывает ошибку разбора.

В GUI есть название, версия, значок OAS, описание, список серверов и Authorize.
Сервер можно сменить; переменные URL заполняются значениями по умолчанию.
Авторизация: apiKey в заголовке, query или cookie, HTTP Basic и Bearer. OAuth2 и
OpenID Connect принимают уже полученный токен и отправляют его как Bearer, без
браузерного входа. Пустой `security` у операции отменяет общую схему.

Операции сгруппированы по тегам (`default`, если тега нет). У метода цвет, путь,
краткое описание и замок, если вызов требует авторизации. Внутри: параметры,
тело запроса с примером и схемой, Try it out и Execute. Пример строится из
`example`, `default`, `const` и `enum`, затем по типу; порядок полей совпадает с
файлом. Ответ показывает код, заголовки, тело, команду curl и время. Локальные
`$ref` раскрываются; цикл или слишком глубокая ссылка не роняют документ.
Относительный URL сервера нужно заменить на абсолютный `http://` или `https://`
перед отправкой. Запрос уходит с потока интерфейса, ждёт до 30 секунд и читает
не больше 512 КиБ тела. В раскрытой карточке кнопка **To HTTP Requests**
переносит операцию в раздел HTTP Requests.

## URL и Base64 в Tools

Каталог Tools содержит URL encode / decode и Base64 encode / decode. Каждый
инструмент открывается в основной рабочей области: Decoded text сверху,
закодированный текст снизу. Оба поля редактируются и синхронизируются автоматически,
у каждого есть Copy. Разделитель регулирует высоты, поля прокручиваются независимо.
Clear очищает текущий инструмент; возврат в каталог и переключение разделов
сохраняют отдельные буферы каждого инструмента до закрытия проекта.

URL кодирует UTF-8 как URL component: сохраняет A–Z/a–z/0–9 и -._~, пробелы
превращает в %20, буквальный плюс — в %2B. Form encoding (+ for spaces) переключает
на form-urlencoded: пробелы становятся +, плюс при декодировании означает пробел.
Base64 использует стандартный алфавит и padding при кодировании; декодирование
принимает также строки без padding и с ASCII whitespace/переносами строк.

При ошибочном/неполном вводе или результате вне UTF-8 показывается ошибка;
исходный ввод и последний корректный результат в другом поле сохраняются.
Преобразования выполняются локально в фоне; текст не отправляется в сеть и не
сохраняется на диск. Лимит редактируемого ввода — 2 MiB.

## YAML / YML

`.yaml` и `.yml` (без учёта регистра) поддерживают Tree-sitter подсветку ключей,
строк, чисел, boolean/null, комментариев, anchors, aliases и tags. Индексирование
YAML не выполняется, PHP LSP и PHP-каталоги для этих документов не используются.
В старых проектах с сохранённым списком языков включите YAML в Settings → Languages.

Reformat Code форматирует документ либо выделение по профилю YAML из
Settings → File Types; по умолчанию — два пробела. Сохраняются структура списков
и mappings, кавычки, комментарии, anchors/aliases, scalar content и LF/CRLF.
Результат повторно разбирается: изменения структуры или значений отклоняются,
включая небезопасное выделение части вложенного блока. Ошибочные отступы нельзя
однозначно восстановить — синтаксические ошибки нужно исправить до форматирования.
Табуляция как отступ профиля отклоняется. Undo отменяет форматирование целиком.
Enter сохраняет отступ текущей строки; вставка YAML сохраняется дословно,
чтобы не менять смысл многострочных значений и скриптов в `|` / `>`.

## Текстовый движок

`nozhik-buffer` зависит от `core` и `event_bus` и работает без UI, runtime
и файлового I/O. Ropey хранит UTF-8 по чанкам; снимки используют copy-on-write.
`line` и `lines` возвращают заимствованные `RopeSlice` для виртуального viewport.
Правки и поиск используют байтовые диапазоны с проверкой границ Unicode scalar;
комбинированные символы и эмодзи сохраняются, навигация по графемам будет в UI.
LF и CRLF сохраняются без нормализации; одиночный CR считается текстом.

Транзакция атомарно заменяет непересекающиеся диапазоны исходного текста.
Курсоры сохраняют направление выделения и сливаются при коллизиях, включая
соприкосновение границ. Undo/redo восстанавливает текст и курсоры, поддерживает
явные группы ввода и точку сохранения (`is_dirty`, `mark_saved`).
`SearchEngine` ищет литералы и Regex непосредственно по чанкам через
`regex-cursor`, в том числе через границы строк, без промежуточного `String`.
События `BufferEvent::Modified` и `CursorChanged` содержат ревизию;
после отставания подписчик получает актуальный `snapshot()` у владельца.

```rust
use nozhik_buffer::{BufferId, SearchEngine, TextBuffer};

let mut buffer = TextBuffer::load_from_str(BufferId(1), "Привет\n");
buffer.insert(12, " 🦀")?; // байтовое смещение перед LF
let matches = SearchEngine::literal("🦀")?.find_all(&buffer);
assert_eq!(matches, vec![13..17]);
buffer.undo()?;
assert!(!buffer.is_dirty());
```

Файловый worker и реестр документов UI интегрированы с TextEditorView.
UI выделяет уникальные `BufferId`, ввод проходит через EditTransaction,
а успешный ответ сохранения очищает dirty только для той же ревизии.

## Настройки

`directories::ProjectDirs::from("dev", "Nozhik", "Nozhik")` определяет каталог.
Приложение выводит фактический путь в stderr перед запуском окна. Типичные пути:

- Windows: `%APPDATA%\Nozhik\Nozhik\config\settings.toml`.
- macOS: `~/Library/Application Support/dev.Nozhik.Nozhik/settings.toml`.
- Linux: `$XDG_CONFIG_HOME/nozhik/settings.toml` или `~/.config/nozhik/settings.toml`.

```toml
tab_width = 4
font_size = 14
theme = "dark"
```

`theme` — `dark` (New UI Dark, стандарт), `light` (New UI Light) или
`catppuccin` (Catppuccin Mocha). Палитра лежит в
`crates/ui/assets/color-schemes.json`. Settings → General переключает схему
сразу. Подсветка синтаксиса по умолчанию следует выбранной схеме; для типа
файла можно оставить Muted или Plain Text.

Отсутствующий файл и отсутствующие поля используют defaults. Неизвестные поля,
повреждённый файл, неверные значения и ошибки доступа возвращают ошибку;
приложение сообщает её и завершает запуск. Исходный файл не перезаписывается.
При первом запуске настройки существуют только в памяти. Явный `save()`
создаёт каталог и сохраняет файл через временный файл в том же каталоге.
`ConfigManager::from_path` также поддерживает `.json`. Автоматического наблюдения
за файлом нет: вызывайте `reload()` на рабочем потоке.

## Графический интерфейс

В Git выбор ветки и действия Fetch/Pull/Push занимают один ряд над Changes/History,
справа от левой полосы инструментов. Имя проекта отображается во вкладке проекта;
повторного заголовка репозитория нет. Fetch доступен и при ожидающих Pull/Push.

Квадратные кнопки **Problems** и **Terminal** находятся внизу левой полосы
инструментов; остальные инструменты остаются сверху. Нижнее окно открывается
справа от полосы, под деревом файлов и редактором. Повторный клик по активной
кнопке сворачивает окно; размер терминала сохраняется при повторном открытии.

**Problems** хранит ошибки текущей сессии проекта. Сейчас в списке одна
раскрывающаяся вкладка **Project**: на ней цифра — сколько проблем, внутри —
карточки. Сюда попадают общие сбои, в том числе неверная авторизация Git,
подключение к базе, SSH и другие настройки. Новая проблема на несколько секунд
появляется справа снизу. Серый цвет с синей «i» — сведения, тёплый с оранжевым
«!» — предупреждение, красноватый — ошибка, красный — критический сбой.
Окно само плавно исчезает; крестик справа сверху закрывает его сразу. Запись
в Problems при этом остаётся. Повтор того же сообщения новое окно не открывает.

Запуск: `cargo run -p app`. Кликните по тексту для фокуса редактора.
Ввод, Backspace/Delete, Enter/Tab, стрелки, Home/End, Shift-выделение,
Ctrl/Cmd+A, Ctrl/Cmd+Z и Ctrl/Cmd+Shift+Z работают с TextBuffer.
Закрытие изменённой вкладки или окна показывает **Save All / Discard / Cancel**.
Save All ждёт подтверждения записи актуальных ревизий, в том числе SFTP и SQL.
Ошибка записи оставляет текст и окно открытыми. Закрытая вкладка освобождает
буфер/историю/результаты; Recent Files хранит до 30 путей для повторного открытия.

Вкладки редактора занимают одну строку и прокручиваются горизонтально колесом
или трекпадом. При переполнении справа появляется квадратная кнопка со стрелкой:
её меню содержит только полностью или частично скрытые сейчас вкладки. Размер меню
подстраивается под содержимое, максимум — половина ширины и высоты области редактора;
длинный список прокручивается, длинные имена сокращаются с подсказкой полного пути. Выбор
активирует вкладку и прокручивает к ней. Кнопка `…` открывает **Go to File…** (поиск на Files),
**Close All Tabs** (все файловые вкладки с подтверждением несохранённых правок)
и **Close Unmodified Tabs** (закрывает только файлы без изменений). SQL-консоли
сохраняют свои отдельные кнопки закрытия и не входят в эти файловые команды.

Search Everywhere: Double Shift (интервал до 400 мс), Ctrl/Cmd+Shift+A
или лупа на тулбаре. Стрелки выбирают результат, Enter открывает, Esc закрывает.
Ctrl/Cmd+Shift+O и Ctrl/Cmd+E пока открывают тот же поиск. Вкладки: All, Classes,
Files, Actions, Text и Recent. Вкладки Symbols нет. Files ищет имя по всему дереву
проекта, включая пути вне языкового индекса и пути из `.gitignore`; файлы
поддерживаемых языков стоят выше остальных. Text и All ищут буквальную строку
во всех файлах проекта: сначала в индексе поддерживаемых языков, затем в остальных,
и пока чтение идёт, в списке крутится индикатор. Повтор того же запроса берёт
результаты из памяти. Кэш сбрасывается при изменении файла, при смене проекта и
при выходе. Открытый буфер показывается вместо копии с диска. Classes показывает
объявления классов PHP и селекторы CSS. Список результатов занимает большую часть
высоты окна. Ctrl/Cmd+F открывает поиск по файлу и сразу ставит курсор в поле Find.
Двоичные файлы, файлы больше 2 МиБ и каталоги `.git` / `.nozhik` в текстовый поиск
не входят; на экран попадает не больше 1000 совпадений и 20 на файл.
Include non-project items зарезервирован. Шестерёнка открывает настройки активного проекта. Единая левая панель содержит Project, Git, SSH и Database.
Их окна открываются слева, повторный клик скрывает выбранное окно.
Нижняя кнопка Terminal открывает PTY-терминал.

Git → History: коммиты и файлы выбираются кликом по всей строке.
Shift выделяет диапазон коммитов, Cmd/Ctrl переключает отдельные строки. Правый
клик сохраняет группу, если строка уже выделена, иначе выбирает только эту строку.
Одиночное меню содержит Amend, Reset (soft/mixed/hard), Checkout, Reorder, Revert,
создание ветки/тега, Cherry-pick, Copy SHA/Tag и View on GitHub. Для группы доступны
Cherry-pick, Squash последовательных коммитов, Reorder и Copy SHAs. Окна действий
подтверждают параметры; cherry-pick выбирает локальную или создаёт новую ветку,
reorder перемещает выбранные коммиты кнопками/стрелками ↑/↓ (Enter применяет).
История следует первым родителям; повторное применение merge-коммитов использует
первого родителя и выпрямляет слияние. Root-коммиты нельзя replay/revert/squash.
Переписывание/cherry-pick/revert требуют чистого диска/index; amend включает только
уже staged изменения. Конфликтующие replay/revert отклоняются до изменения файлов
и refs. При групповом выборе справа показан общий список файлов всех выбранных коммитов
без повторов. Для каждого файла diff берётся из самого нового выбранного коммита,
в котором он менялся; бейдж и подсказка отмечают другие выбранные коммиты с этим
же путём. Пропущенные коммиты не добавляют файлы в список. Контекстное меню файла
History содержит Reveal in File Manager, Open in Nozhik, Open with Default Program,
Copy File Path, Copy Relative File Path и View on GitHub. Открытие использует текущую
рабочую копию; для отсутствующих файлов локальное открытие недоступно. GitHub
открывает историческую версию, а для удаления — файл в первом родителе.
Origin показывает Fetch / Pull / Push / Pull & Push с бейджами ↓/↑ количества
коммитов behind/ahead (данные обновляются после Fetch). Pull & Push объединяет
расхождение merge-коммитом и отправляет без force; при конфликте открывается
разрешение слияния, после Continue нужно явно нажать Push. Изменённые
файлы находятся в отдельной колонке с изменяемой шириной; справа отображается diff.
Мышь выделяет текст diff для Cmd/Ctrl+C или Copy в контекстном меню. Колесо и
вертикальная/горизонтальная полосы прокрутки перемещают содержимое.
В Changes и History PHP/PHTML подсвечиваются той же синтаксической палитрой,
что и редактор (с учётом Settings → Languages и выбранной темы файла).
Стрелки ↑/↓ в пропусках раскрывают ещё 20 строк соответствующей версии Git;
их можно нажимать повторно до начала/конца файла. Между изменениями доступны
оба направления. Для бинарных и превышающих лимиты файлов полный контекст
недоступен; обычный ограниченный diff сохраняется.

## Работа с проектами и файлами

`cargo run -p app -- /path/to/project` открывает указанную рабочую папку;
без аргумента открывается текущая директория. В Windows передайте обычный путь,
например `cargo run -p app -- 'C:\Projects\demo'`. Для смены проекта в панели
Project введите путь папки и нажмите **Open** либо нажмите **Choose folder…**
для стандартного окна выбора папки ОС. Эти элементы отображаются только без
открытого проекта; смена проекта всегда доступна в меню File. Под кнопками расположен список **Recent
Projects**, отсортированный по последнему успешному открытию. Клик открывает
выбранный проект; история сохраняется между запусками в `recent_projects.json`
рядом с `settings.toml`. Недоступный путь сообщает ошибку и не меняет историю.
Смена проекта сохраняет буферы предыдущего проекта в памяти, включая
несохранённые изменения.

**File → Open File / Folder…** сразу открывает системный диалог: на macOS можно
выбрать файл или папку в одном окне; Windows/Linux используют режим выбора папки,
а **File → Open File…** открывает системный выбор файла. **File → Recent Projects >**
показывает ту же историю в подменю, открывающемся при наведении.
**File → New…** предлагает выбрать родительскую папку ОС, затем ввести имя проекта.
После подтверждения создаётся новая папка и открывается как проект; существующие
папки не перезаписываются. Ошибка сохраняет форму для исправления имени.
**New File** по-прежнему создаёт отдельный файл по введённому пути.

Клик по стрелке `›` / `⌄` или строке папки раскрывает или сворачивает каталог; его непосредственные дети
загружаются в фоне при первом раскрытии. Папки идут перед файлами, обе группы
отсортированы по алфавиту. Двойной клик по файлу или Enter на выбранном файле
открывает вкладку; повторное открытие активирует существующий буфер.

В заголовке Project доступны четыре кнопки с подсказками: **Select Opened File**
выделяет активный локальный файл текущего проекта, раскрывает его родительские
папки и прокручивает дерево к файлу; **Expand Selected** полностью раскрывает
выбранный каталог со всеми потомками, загружая их в фоне; **Collapse All**
сворачивает все каталоги и отменяет незавершённое раскрытие; **Hide** скрывает
панель, сохраняя её состояние. Вернуть панель можно кнопкой Project на левой
полосе. Клик по папке также выделяет её; без выбранного каталога Expand Selected
недоступна. Select Opened File недоступна для SQL, SFTP и файлов другого проекта.

**Ctrl/Cmd+S** сохраняет текущий файл. Запись выполняется в фоне через временный
файл в том же каталоге с сохранением permissions, затем файл заменяется.
Dirty снимается только после успеха и только для записанной ревизии; правки,
сделанные во время сохранения, остаются dirty. Ошибки видны в status bar и stderr.
Нужны права записи на файл и на его каталог. Удалённый до сохранения файл
возвращает ошибку. Межпроцессных блокировок и слияния внешних правок пока нет.

В Search Everywhere выберите **Files**, введите часть относительного пути,
выберите результат стрелками и нажмите Enter. Fuzzy-поиск выполняется в фоне
по всему индексу, включая ещё не раскрытые каталоги; выдача ограничена 100 файлами.
Пути в поиске отображаются через `/`, запросы принимают и `\`, и `/`.

Дерево показывает игнорируемые Git пути красным текстом на приглушённом красном
фоне. Уже отслеживаемые файлы и каталоги с отслеживаемыми потомками остаются
обычными, даже если родитель внесён в `.gitignore`. Само имя `vendor`, `target`
или `node_modules` не делает путь исключённым. Игнорирование влияет только на
цвет: файлы остаются доступны в поиске по именам и языковых инструментах.
Без Git-репозитория подсветка использует `.gitignore`/`.ignore`. `.git` скрыта.
Тесты и настройки линтеров выделяются зелёным, включая потомков тестовых папок;
исключение имеет приоритет над зелёной подсветкой. Папки имеют иконки и стрелки
состояния, основные типы файлов — компактные значки, остальные — серый документ.
Символические ссылки при обходе не раскрываются. Watcher объединяет изменения
одного пути за 150 мс; create/remove/rename обновляют дерево и индекс, включая
отображаемые исключённые пути, кроме внутренних файлов `.git`.
Изменения открытых файлов сообщаются в статусе; буферы сохраняют свой текст,
автоматического reload/merge нет. Собственные сохранения также видны watcher.

NUL в первом килобайте показывает **Binary file not supported**; такой буфер
нельзя редактировать или сохранять. Невалидный UTF-8 возвращает ошибку открытия.

## Встроенный Git-клиент

Откройте папку внутри существующего Git-репозитория. Кнопка `⑂` на левом
тулстрипе или **Ctrl/Cmd+Shift+G** открывает Changes/History. Если открыта
подпапка репозитория, Git-панель показывает весь репозиторий; пути в ней
относительны его корню.

- **Changes**: фильтр по пути, цветные статусы, staging/unstaging файла и Select All.
  Чекбоксы управляют настоящим Git index. Промежуточный чекбокс означает наличие
  staged и unstaged изменений одновременно; снятие снимает staging, повторная
  установка включает текущую дисковую версию файла целиком.
- **Commit**: обязательный Summary и необязательный Description. Кнопка
  `Commit N files to branch` или **Ctrl/Cmd+Enter** в Git-панели записывает index.
  Нужна настроенная Git identity (`user.name` и `user.email`). Успех очищает поля,
  обновляет статус и History; оставшиеся unstaged изменения сохраняются в списке.
- **Diff Viewer**: unified hunks, старая/новая нумерация, зелёные добавления и
  красные удаления, моноширинный шрифт. По умолчанию сравниваются HEAD и рабочее
  дерево; **Staged only** показывает именно содержимое будущего коммита.
- **History**: карточки коммитов, автор/относительное время, описание, полный и
  короткий SHA с копированием, затронутые файлы и их исторические diff. Merge
  commits сравниваются с первым родителем. История загружается по 100 записей
  до 10 000; карточки и строки diff виртуализированы.
- **Ветки и remotes**: верхняя панель и заголовок показывают текущую ветку.
  **Current Branch** открывает фильтруемый список локальных и удалённых веток
  с текущей веткой, группировкой и возрастом коммитов. **New Branch** создаёт ветку
  от HEAD с сохранением текущих правок. При переключении с изменениями доступны
  **Leave my changes** (именованный stash исходной ветки, включая untracked-файлы;
  восстанавливается при возврате) и **Bring my changes** (безопасный checkout,
  который отклоняет перекрывающиеся изменения). Удалённая ветка получает локальную
  tracking-ветку. Toolbar предлагает Fetch/Pull/Push/Publish origin; контекстное
  меню и стрелка также содержат эти команды и Refresh.
  Отображаются ahead/behind относительно upstream. Push не использует force;
  для новой ветки устанавливается upstream. `origin` должен быть настроен заранее.

Git status обновляется после сохранений/уведомлений watcher с debounce 200 мс,
а для открытого репозитория дополнительно проверяется раз в 3 секунды, включая
внешние изменения `.git`. Status, diff, index, history, commit и сеть исполняются
в выделенном worker; результаты будят UI. SSH использует агент, HTTPS —
настроенный credential helper. Секреты не вводятся и не хранятся в интерфейсе.

В контекстном меню файла **Discard Changes…** запрашивает подтверждение перед
восстановлением его index/дисковой версии из HEAD (untracked-файл удаляется).
Переименование восстанавливает старый путь и удаляет новый; если старый путь уже
занят, операция отклоняется. **Ignore File** добавляет точный экранированный путь
в корневой `.gitignore`; уже tracked-файл это не удаляет из index.
Cmd/Ctrl-клик и Shift-клик выделяют несколько файлов. Их меню содержит групповой
Discard с подтверждением, Ignore выбранных путей/расширений, Include/Exclude,
копирование абсолютных/относительных путей, открытие в Nozhik/программе по
умолчанию и показ в файловом менеджере. Поле Filter и его меню отбирают пути,
включённые, unstaged и конфликтные файлы.

Git-окно использует собственную тёмную палитру, строку репозитория/ветки/сети,
фиксированные строки файлов и форму коммита внизу; ширина Git-sidebar сохраняется
отдельно от Project. Фоновые status/diff/history-запросы не отключают кнопки и
не очищают отображаемый diff. Кэш последних восьми diff и request ID сохраняют
содержимое и прокрутку при переключении, отбрасывая устаревшие ответы.

**Choose a branch to merge into …** открывает **Merge into …**. Предварительный
просмотр считает конфликтные файлы без записи в репозиторий; само слияние требует
чистого index/рабочего дерева и настроенной identity. Оно создаёт merge-коммит
с двумя родителями, а при конфликте показывает баннер и **View conflicts**.
**Open in Nozhik** открывает файл в редакторе. После удаления всех маркеров и
сохранения **Continue Merge** становится активной, повторно проверяет диск,
добавляет разрешённые файлы в index и завершает merge-коммит. Бинарные, удалённые
и структурные конфликты требуют явного **Include Selected Files** после разрешения.
**Abort Merge** запрашивает подтверждение и восстанавливает HEAD.
Pull поддерживает только fast-forward при чистом index/рабочем дереве;
расхождение веток возвращает ошибку. Rebase, submodule-операции, hooks и GPG signing
пока не поддерживаются.
Git действует на дисковые версии: несохранённый текст редактора в коммит не входит.
После checkout/pull/discard буферы редактора сохраняются в памяти без автоматического
reload — это также относится к последующему сохранению устаревшего буфера.
Binary/oversized diff показывает заглушку; текстовая выдача ограничена 2 MiB,
50 000 строк и 4096 символами на строку с явной отметкой о сокращении.

## Расширяемость и горячие клавиши

`nozhik-plugin-host` обнаруживает `plugin.json` в подпапках `~/.nozhik/plugins/`
и `<project>/.nozhik/plugins/`. Расширение поставляется отдельно от IDE:
строгий манифест регистрирует языковые ассоциации, команды, defaults настроек
и описания вкладок; optional executable запускается отдельным процессом
по событиям открытия файла или вызова команды. SemVer проверяет минимум IDE
и зависимости, конфликты и циклы видны в диагностике.

Все вызовы расширений выполняются в фоновом host с JSON-RPC/stdio, очередью,
таймаутом 3 секунды и лимитом ответа 64 KiB. Падение расширения переводит его
в Failed и удаляет вклады. Процесс работает с правами пользователя;
OS sandbox и произвольные языковые/LSP/БД API для внешних плагинов ещё не реализованы.
Встроенная PHP-поддержка использует отдельный language_support и LSP-протокол.

**Settings → Plugins…** или команда **Plugins** в Search Everywhere открывает
список с версией, автором, статусом и переключателем Enabled. Можно включать
и отключать расширения без перезапуска; зависимые плагины отключаются вместе
с зависимостью. **Rescan installed plugins** перечитывает каталоги. В текущей
версии состояния переключателей действуют до следующего scan/запуска.
Раздел Extension tabs показывает декларативные вкладки расширений.

**Search Everywhere → Actions** динамически читает потокобезопасный реестр
действий, фильтрует доступность по контексту и показывает shortcuts.
Enter запускает выбранную команду. `when` поддерживает `editorOpen`,
`editorFocus`, `selectedFile`, `projectOpen`, `&&` и `!`.

Файл `~/.nozhik/keymap.json` переключает профили `JetBrains`, `VSCode`, `Custom`
без перезапуска (проверка раз в секунду):

```json
{
  "profile": "VSCode",
  "bindings": [
    {
      "chord": { "key": "R", "primary": true, "alt": true },
      "action": "php.runScript",
      "when": "editorOpen"
    }
  ]
}
```

`primary` — Ctrl на Windows/Linux и Cmd на macOS. Последний binding одинакового
сочетания заменяет предыдущий; ошибочный reload сохраняет текущий профиль.
VSCode использует Ctrl/Cmd+Shift+P для поиска, JetBrains — Ctrl/Cmd+Shift+A;
Double Shift доступен в обоих. Внутренние сочетания текстового редактора
и Git commit пока принадлежат соответствующим views.

Полный манифест, IPC-протокол и примеры API:
[руководство автора расширений](docs/ai/plugin-authoring-guide.md).


## Поддержка языков: PHP

Встроенная конфигурация `org.nozhik.php` связывает `.php` и `.phtml` с PHP.
Tree-sitter и bundled `highlights.scm` работают без внешнего сервера: ключевые слова,
строки, комментарии, функции, типы и переменные окрашены палитрой Darcula/New UI.
Разбор выполняется в отдельном worker с повторным использованием изменённого дерева;
UI рисует видимые строки, сдвигает сохранённые цвета и code lenses вместе с правкой,
затем заменяет их результатом актуальной ревизии без промежуточного сброса оформления.
Вложенные HTML/CSS/JavaScript грамматики пока не подключены.

Для диагностики и интеллектуальных функций установите один LSP-сервер и добавьте
его executable в `PATH`, с которым запускается Nozhik:

- [Phpactor](https://phpactor.readthedocs.io/en/master/usage/getting-started.html):
  IDE запускает `phpactor language-server` ([stdio](https://phpactor.readthedocs.io/en/master/lsp/running.html)).
- [Intelephense](https://github.com/bmewburn/intelephense-docs/blob/master/installation.md):
  установите Node.js/npm, затем `npm install -g intelephense`; IDE запускает
  `intelephense --stdio`.

Phpactor имеет приоритет при наличии обоих. На Windows ищутся `.exe`, `.cmd`,
`.bat`; на Unix требуется executable permission. После изменения PATH перезапустите
IDE. При отсутствии сервера статус и stderr показывают инструкцию установки,
подсветка остаётся доступной. Сервер запускается при первом PHP-документе проекта;
смена проекта пересоздаёт сервер. Файл для LSP может ещё не существовать на диске.

Ошибки/предупреждения отображаются волнистыми линиями и маркерами gutter;
наведение на диапазон показывает сообщение. Статус-бар считает диагностики
открытых PHP-вкладок. Ввод букв, `$`, `\`, `->`, `::` запрашивает completion после
200 мс покоя. Стрелки выбирают подсказку, Enter/Tab принимают, Esc закрывает;
поддерживаются серверные textEdit и дополнительные правки (например imports)
одной undo-транзакцией. При наведении показывается hover с базовым Markdown
(заголовки, код, жирный текст, списки). Ctrl/Cmd+клик или F12 открывает первый
результат definition и прокручивает редактор к строке.

LSP использует UTF-16, stdio JSON-RPC Content-Length, initialize/initialized,
didOpen/didChange/didClose и shutdown/exit. didChange объединяется за 200 мс;
перед интерактивным запросом отправляется актуальная версия. Full и incremental
синхронизация выбираются по capabilities сервера (incremental — замена прежнего
документа целиком). Запросы имеют таймаут 5 секунд; зависший сервер не блокирует
рендеринг и Tree-sitter. При выходе cleanup ограничен по времени, затем процесс
принудительно завершается. LSP-сервер работает с правами пользователя.

Текущий объём LSP — client core: серверные snippets/resolve, code actions, rename/refactoring,
semantic tokens, диагностика закрытых файлов, пользовательские LSP settings и
автоматический restart после падения пока отсутствуют. PHP contribution встроен
и не управляется переключателем executable-плагинов в Settings. Локальная библиотека
предоставляет `LanguageService::with_server` для явного пути/аргументов сервера.


## LLM-консоль

Кнопка **LLM console** (робот) внизу левой полосы, над Terminal, открывает
отдельные локальные PTY-вкладки в каталоге текущего проекта. Запустите `grok`
или `codex` обычной командой. На macOS/Linux агент определяется по процессу
переднего плана, а не по тексту вывода; macOS учитывает также native CLI внутри
npm/node-обёртки в той же foreground-группе. На Windows пока доступен обычный
терминальный ввод этой панели, автоматическое определение и кнопки контекста
ещё не подключены. SSH, Docker и удалённые CLI в эту интеграцию не входят.

Для распознанного агента появляются **Open files**, **Selection** и
**Attach file…**. Open files добавляет ссылки на UTF-8-снимки всех открытых
локальных текстовых вкладок, включая несохранённые правки; исходники не
сохраняются поверх диска. Selection добавляет текущее выделение редактора,
исходный путь, revision, строки и UTF-8 byte columns (с 1, конец исключён).
Выделение остаётся в буфере при переходе фокуса в консоль; поддерживаются
несколько выделений. SFTP-вкладки и бинарные placeholder-вкладки исключены.

Файлы можно выбрать по кнопке или перетащить из Finder/файлового менеджера
в область LLM-панели. Изображения вставляются отдельным bracketed paste с
локальным путём: Codex/Grok преобразуют его в своё нативное вложение. Для других
форматов добавляется ссылка с просьбой прочитать файл; возможность разбора
PDF/архивов и прочих форматов зависит от агента и его инструментов.
Вложения копируются в отдельный временный каталог, чтобы исходный файл мог
переименовываться независимо. Пределы: 20 MiB на файл, 16 файлов за drop,
256 MiB временного контекста на LLM-панель проекта; выделение — до 64 KiB.
Подготовка и файловый I/O выполняются worker; временные копии удаляются при
закрытии проекта/приложения. Скрытие панели сохраняет сессии и вложения.

Контекст добавляется в черновик без Enter. Перед вставкой повторно проверяются
вкладка, PID/тип агента и bracketed paste; writer дополнительно проверяет,
что процесс ещё занимает foreground-группу после предыдущего клавиатурного
ввода. При смене агента/закрытии вкладки показывается ошибка. Управляющие
терминальные символы в контексте отклоняются. Для Grok нужна обычная локальная
авторизация CLI; Nozhik не выполняет вход за пользователя.

## Встроенный терминал

Откройте проект и нажмите **Alt+F12** (на Mac — Option+F12, при необходимости Fn)
или **Terminal** на нижнем тулстрипе. Терминал открывается в текущем проектном
каталоге. В Search Everywhere → Actions доступно действие `ui.terminal`; его
сочетание можно изменить в пользовательском Keymap. JetBrains/VSCode profiles
включают Alt+F12 по умолчанию; Custom использует только явные bindings.

Верхняя строка панели содержит вкладки, **+** для новой сессии, **×/Close** для
завершения сессии и **—** для сворачивания панели. Скрытые сессии продолжают работать.
Новая вкладка получает имя Terminal N; OSC title от шелла/TUI может заменить его.
При завершении шелла вкладка закрывается, код выхода отображается в статусе.
При смене проекта существующие терминалы сохраняют свои cwd, новые открываются
в новом проекте. Изменение высоты панели/размера окна меняет геометрию PTY.

macOS/Linux используют `$SHELL` с login-аргументом `-l`, fallback — `/bin/zsh`
на macOS и `/bin/bash` на Linux. Windows использует `%COMSPEC%`, а при его отсутствии
ищет PowerShell, затем cmd.exe. Windows backend — ConPTY; нужен
[Windows 10 1809+ либо Windows 11](https://learn.microsoft.com/en-us/windows/console/createpseudoconsole).
Используется окружение процесса IDE, `TERM=xterm-256color`, `COLORTERM=truecolor`.
Можно запускать установленные `git`, `composer`, `cargo`, `vi`, `htop` и другие
консольные программы; установка этих программ остаётся задачей пользователя.

Клик по сетке передаёт терминалу фокус. Работают Unicode-ввод, Enter, Tab,
Backspace, Escape, стрелки, Home/End, Insert/Delete, PageUp/PageDown и F1–F12.
Ctrl+C отправляет interrupt, Ctrl+D — EOF, Ctrl+Z — suspend (Unix), Ctrl+L —
control-byte для очистки/перерисовки шеллом. Эти байты обрабатывает активная
программа/line discipline. Поддерживаются application cursor keys и bracketed paste.
Вставка из системного clipboard поступает в PTY; одна порция ограничена 64 KiB,
при переполнении очереди появляется ошибка вместо молчаливой потери ввода.

ANSI 16/256 и RGB-цвета, bold/dim/italic/underline/inverse, Unicode wide/combining
cells, статичный блочный курсор и альтернативный экран отрисовываются сеткой.
Колесо мыши просматривает историю до 3000 строк; новый ввод возвращает live screen.
В альтернативном экране история не прокручивается. Запуск, чтение, запись и resize
идут в фоновых потоках; UI получает готовый Arc-снимок без ожидания блокировок.
Закрытие вкладки/IDE останавливает шелл и освобождает PTY; на Unix также завершается
foreground process group. Явно отсоединённые пользовательские процессы не управляются
как отдельное дерево задач. Общий shutdown терминалов ограничен 3 секундами ожидания.

Если программа включает mouse reporting, клики, удержание/перетаскивание и колесо
передаются ей в формате xterm (SGR, UTF-8 или legacy X10). Поэтому кнопки, ссылки,
выделение и прокрутка внутри Grok обрабатываются самим Grok. Его нативное выделение
можно расширять колесом мыши; копирование после release поддерживает также OSC 52.
Запись OSC 52 в clipboard принимается только в течение 5 секунд после событий
мыши, ограничена 4 MiB и UTF-8. Чтение clipboard по OSC 52 не поддерживается.

Для локального копирования удерживайте **Shift** при выделении либо нажмите
**Text selection**. Этот режим фиксирует доступный буфер, пока приложение
продолжает работать в фоне. В обычном терминале доступны до 3000 строк истории,
колесо/трекпад, полоса справа, Shift+PageUp/PageDown и автопрокрутка у верхнего/
нижнего края при выделении. Выделение сохраняется между страницами; Copy/⌘C
копирует весь выбранный диапазон. **Copy all** копирует весь доступный буфер.
**Live · Esc** или новый клавиатурный ввод возвращают работающую консоль.
В полноэкранном alternate buffer локальный Text selection фиксирует видимый экран;
длинную историю такого приложения прокручивайте и выделяйте в его нативном режиме.
Если alternate-программа не включает mouse reporting, колесо передаётся стрелками.

Терминал использует JetBrains Mono, Noto Sans Symbols 2 и современный Noto Emoji:
Braille-логотипы, рамки, блоки, Powerline, стрелки и обычные эмодзи отображаются
с fallback и вписываются в ширину своих ячеек. Исходный Unicode в clipboard
сохраняется; автоматические переносы строк терминала склеиваются при копировании.

Текущие границы: до 16 сессий, 200×500 видимых ячеек; нет поиска по истории,
persistent sessions и полного набора xterm-расширений. Сетка не переформатирует
историю как reflow-терминалы; при resize применяются правила vt100. Изменение
размера завершает локальный режим выделения. Отдельный OSC 8 hyperlink renderer
не реализован: ссылки внутри TUI обслуживаются самим приложением через mouse events.


## Docker Compose

Нужны установленный Docker CLI с Compose plugin (`docker compose`) и запущенный
Docker Engine (Docker Desktop, OrbStack или совместимый engine). На macOS также
проверяются стандартные пути Docker CLI для запуска IDE из Finder.

IDE автоматически находит `compose.yaml`, `compose.yml`, `docker-compose.yaml`,
`docker-compose.yml` и dotted variants вроде `docker-compose.prod.yml` в проекте.
Расширения распознаются без учёта регистра. Симлинки и каталоги `.git`, `.nozhik`,
`target`, `node_modules`, `vendor` не обходятся. Docker-файлы получают иконку кита
в дереве и вкладках; кнопка Docker между Database и Snippets активна при
наличии Compose-файлов. Это отдельное обнаружение файлов, без YAML-индекса.

В gutter у `services:` находится запуск всех сервисов, у ключа сервиса — запуск
этого сервиса с его зависимостями (`compose up --detach`). Несохранённые файлы
выбранной конфигурации нужно сначала сохранить. Ошибочный YAML не получает
кнопок запуска. Действия привязаны к точным BufferId/revision.

Панель Docker показывает сервисы и контейнеры выбранной конфигурации, включая
остановленные и ещё не созданные. Стандартный base автоматически объединяется
с conventional override того же семейства; выбранный prod/test/другой variant —
с base, без автоматического подключения остальных variants. Порядок `-f` показан
под кнопками. Compose сам разрешает `.env`, переменные, includes и project name.
Это локальное управление через текущий Docker context, без встроенного daemon.

Доступны запуск всех/одного сервиса, запуск существующего контейнера, остановка
одного/всех контейнеров и Refresh. Удаление контейнеров/томов не выполняется.
Имена проекта недостаточны для доступа: контейнеры дополнительно проверяются по
Compose working-directory label. Коллизия project name с другим каталогом
блокирует операции; задайте уникальное top-level `name:`. Цели операций — immutable
container IDs. Ошибки CLI/engine и отмена показываются в панели; Cancel прекращает
ожидание CLI, состояние уже отправленной Docker операции следует проверить Refresh.
Cancel всегда занимает место в строке кнопок и активен только во время запроса.
Прелоадер появляется только при действиях пользователя (включая Refresh),
в зарезервированном месте строки кнопок. Автообновление выполняется без прелоадера
и не сдвигает список контейнеров.

Клик по контейнеру открывает Info с ID/image/status/mounts/labels и вкладку Logs:
последние 500 строк stdout/stderr с timestamps, обновление каждые три секунды,
пока окно открыто. Open console открывает интерактивный `docker exec -it … /bin/sh`
в нижнем PTY-терминале IDE, в отдельной вкладке `[Docker: <container>]`.
Контейнер должен работать и содержать `/bin/sh`; ошибки отсутствующего shell
остаются видимыми в завершившейся вкладке. Закрытие консоли не останавливает
контейнер. Docker-операции и discovery выполняются worker, независимо от PHP/YAML
language opt-in; фоновые статусы обновляются только при видимой Docker-панели/окне.

## Удалённая разработка: SSH, SFTP и туннели

Кнопка **⇄ Remote Host / SSH** на левом тулстрипе открывает список серверов.
**+ Add SSH host** сохраняет имя, Host, Port (22), User, Auth Type и правила
Local Port Forward. Профили находятся в `ssh_hosts.json` рядом с `settings.toml`
в каталоге конфигурации IDE; это пользовательский `config/ssh_hosts.json`,
а не файл в рабочем проекте. Повреждённый JSON не перезаписывается автоматически.
Форма позволяет добавлять, редактировать и удалять несколько правил проброса.
**Edit** изменяет сохранённый хост; **Delete…** удаляет его после подтверждения.
Смена имени/адреса/пользователя/метода входа удаляет прежний сохранённый пароль,
закрывает старое соединение и требует нового входа. Открытые файлы сохраняют
правки в памяти; после смены хоста их нужно заново открыть через SFTP для
дальнейшего удалённого сохранения. Удаление профиля удаляет его сохранённый
пароль, но оставляет отдельную запись доверия ключу сервера.

Отпечаток ключа вводить не нужно. При первом подключении Nozhik получает ключ
сервера и показывает **Trust SSH server?** с адресом и SHA256 fingerprint.
**Trust and Continue** запоминает ключ и продолжает подключение; **Cancel**
отменяет попытку, не сохраняя доверие и не отправляя пароль. При необходимости
отпечаток можно сверить с администратором сервера.

Подтверждённые ключи хранятся в `ssh_known_hosts.json` рядом с настройками,
отдельно для каждой пары host/port. Следующие соединения проверяются
автоматически. Изменившийся ключ вызывает блокировку и отдельный диалог;
старый ключ автоматически не заменяется. Повреждённый trust-файл не
перезаписывается. Старые профили с `host_key_sha256` продолжают проверять
свой pin; для новых профилей поле необязательно и отсутствует в форме.
Host certificates и политика доверия CA пока не поддерживаются.

Аутентификация: **Password**, **Private Key** (OpenSSH, RSA/Ed25519, путь
`~/.ssh/id_ed25519` или `~/.ssh/id_rsa`) и **SSH Agent**. На Unix используется
`SSH_AUTH_SOCK`, на Windows — `\\.\pipe\openssh-ssh-agent`. Пароль или
парольная фраза запрашиваются после проверки/подтверждения ключа сервера.
Поле Password получает фокус автоматически; Connect или Enter продолжает вход.
Пустая фраза допустима для незашифрованного ключа. Существующее соединение
переиспользуется.

Для сохранённого профиля доступна опция **Save password in system credential
store**. После успешной авторизации пароль/фраза сохраняются в **macOS Keychain**,
**Windows Credential Manager** или **Linux Secret Service** (разблокированный
сеанс GNOME Keyring/KWallet с Secret Service API). Следующий вход использует
сохранённый секрет после проверки ключа сервера. При неверном пароле или
недоступном хранилище IDE запрашивает новый ввод. **Forget password** удаляет
секрет из хранилища; отключение опции при успешном входе также удаляет старый.
Системное хранилище может запросить разрешение/разблокировку. Ошибка доступа
показывается пользователю; открытого файлового fallback нет.

В `ssh_hosts.json` хранится только boolean `save_password`, сами секреты
не попадают в JSON/логи; собственные временные буферы секретов очищаются при
освобождении. При тестировании ещё не сохранённого профиля пароль используется
только для текущего входа: сначала сохраните профиль, чтобы включить запоминание.

- **Test Connection** выполняет SSH-рукопожатие, проверку ключа и авторизацию.
- **Open Terminal** открывает вкладку `[SSH: имя]` в нижнем Terminal. Действуют
  ANSI-цвета, scrollback, alternate screen и клавиатура существующего терминала;
  геометрия передаётся серверу через `window-change`, TERM — `xterm-256color`.
  Закрытие вкладки закрывает её канал; **Disconnect** закрывает весь транспорт.
- **Browse SFTP** открывает домашний каталог (`.`). Раскрытие папки лениво
  загружает детей; двойной клик по файлу открывает обычный TextBuffer. Файл
  кэшируется в приватном временном каталоге; **Ctrl/Cmd+S** загружает текущий
  снимок обратно по SFTP. Dirty снимается только для сохранённой ревизии.
  При ошибке/обрыве правки остаются в памяти, локальная запись вместо SFTP
  не выполняется. Для внешних изменений используйте **Refresh**.
- **Start Tunnels** явно запускает сохранённые правила. Слушатель доступен
  только на `127.0.0.1`; `local_port: 0` выбирает свободный порт. Фактические
  адреса показываются в status bar. **Stop Tunnels**, Disconnect и выход из IDE
  закрывают слушатели и активные потоки. Пример: `127.0.0.1:15432` →
  `127.0.0.1:5432` с точки зрения SSH-сервера; клиент БД использует локальный порт.

SSH/SFTP работают в фоне. Connect/auth/channel/SFTP имеют deadline 15 секунд;
keepalive через 20 секунд закрывает транспорт после трёх пропущенных ответов.
Кэш содержит до 128 каталогов на соединение с TTL 30 секунд; upload и Refresh
сбрасывают его. Туннель ограничен 64 одновременными потоками.

Ограничения: удалённый редактор принимает UTF-8 до 16 MiB, бинарные файлы
отклоняются; SFTP upload перезаписывает файл с обрезанием, без атомарного rename,
блокировки и проверки внешних изменений. При сбое возможна частичная запись
на сервере. Remote workspace, удалённые LSP/Git, SSH config/ProxyJump,
keyboard-interactive/2FA и автоматический reconnect пока не реализованы.


SSH shell setup ждёт именно подтверждение PTY/shell: служебные
`WindowAdjusted` и `XonXoff` не считаются отказом, ранний вывод сохраняется
для терминала. Настоящие отказы различают `rejected PTY request` и
`rejected shell request`; причиной может быть запрет на стороне сервера.
Опциональная локальная проверка настоящим OpenSSH (Unix, требуется sshd):

```sh
cargo test -p nozhik-remote-ssh system_openssh_shell_and_sftp -- --ignored
```

Тест запускает отдельный sshd только на localhost с временными ключами и
конфигурацией, не меняя пользовательский `~/.ssh` или системный sshd.


## SFTP Deployment

В **Settings → SFTP Deployment** выберите существующее SSH-соединение проекта,
укажите абсолютный POSIX-путь **Remote project root** (например `/var/www/app`)
и нажмите **Apply deployment**. Для проекта сохраняется только один сервер;
**Disable deployment** отключает отправку. Настройка хранится в проектном
`.nozhik/settings.toml`, пароли и ключи туда не копируются. SSH-профили по-прежнему
создаются в Remote Host / SSH; используются прежние проверка host key и credentials.

После настройки правый клик по файлу, папке или корню дерева проекта содержит
**SFTP Deploy**. Пути сохраняются относительно локального корня: файл `src/a.php`
попадает в `/var/www/app/src/a.php`; отправка корня загружает его содержимое без
дублирования имени проекта. Папки передаются рекурсивно, включая пустые; нужные
каталоги на сервере создаются автоматически. Совпадающие обычные файлы
перезаписываются; остальные файлы на сервере не удаляются. Перед отправкой нужно
сохранить изменения в выбранном файле/поддереве: несохранённые буферы не отправляются.

В Git → **History** выберите один коммит и нажмите **SFTP Deploy Files** справа
от Pull/Push и его меню. Коммит задаёт только список изменённых путей: отправляются
текущие сохранённые файлы проекта, а не исторические версии. Под кнопкой постоянно
показано это пояснение. Несохранённые изменения выбранных файлов требуют сохранения;
изменения остальных файлов не мешают. Отсутствующие файлы (включая удаления),
каталоги, симлинки, внутренние пути и пути вне открытого проекта пропускаются;
каталоги из Git не обходятся рекурсивно, удаления на сервере не выполняются.
Во время загрузки деталей коммита, выбора нескольких коммитов или активной передачи
кнопка недоступна.

Прогресс и **Cancel deployment** показываются над деревом проекта и в Git. Передача идёт
в отдельном worker по SFTP через проверенный SSH transport, не блокирует UI и
не ограничивается 35-секундным общим таймаутом SSH-команд. Сетевые операции имеют
свои deadlines. Отмена/закрытие проекта останавливают передачу; уже отправленные
файлы остаются, текущий файл при сбое/отмене может оказаться частично записанным.
Загрузка не является атомарной публикацией проекта и не выполняет rollback.

`.git`, `.nozhik` и вложенные локальные симлинки пропускаются; явный выбор внутреннего
каталога, симлинка или пути за пределами проекта отклоняется. Симлинк самого
настроенного server root может быть разрешён сервером через realpath; внутренние
симлинки в целевых каталогах/файлах отклоняются. Бинарные файлы передаются потоком
по 64 KiB без лимита 16 MiB удалённого редактора. Один запрос ограничен 100000
локальных записей. Смена/удаление профиля или настройки во время ожидания SSH
не перенаправляет старый запрос: требуется повторить SFTP Deploy.


## Встроенный клиент баз данных (Phase 8)

**Database** на левой полосе инструментов открывает Database Explorer в стиле DataGrip.
Кнопка **+** создаёт подключение PostgreSQL, MySQL/MariaDB или SQLite (локальный
путь либо `:memory:`). Укажите имя, host/port/user/database; **Test Connection**
проверяет подключение и аутентификацию, **Save** сохраняет профиль. Для существующего
профиля нажмите **Connect**; **Connect with password…** позволяет повторить вход
с новым паролем после отказа сохранённого. **Refresh metadata** в меню подключения обновляет метаданные.
Дерево повторяет компактное оформление DataGrip: строки 24 px, вложенность 19 px,
синие папки, отдельные иконки таблиц/колонок/ключей/индексов. Первичные ключи
жёлтые, внешние — синие; типы, defaults и количества показаны вторичным цветом.
Клик выделяет строку на всю ширину; группы раскрываются кликом, таблица открывается
двойным кликом. Каждая схема/БД имеет собственный узел, включая единственную
схему подключения. Connect, Refresh metadata, Disconnect, Edit Connection…
Connect with password… и New SQL Console доступны по правому клику на подключении.

Правый клик на **схеме/БД** открывает New SQL console (с уже выбранной схемой),
Modify Schema..., Generate DDL to Clipboard, Run SQL Script... и Export Data to File.
Modify Schema загружает текущие настройки: MySQL/MariaDB — collation и явные
schema grants; PostgreSQL — имя, owner, comment и USAGE/CREATE grants;
SQLite — user_version/application_id. Сверху форма, снизу точный SQL preview,
Apply применяет изменения и обновляет дерево. MySQL/SQLite не предлагают
неподдерживаемое переименование схемы. Права видны в пределах доступа текущего login.

Правый клик на узле **tables** открытого соединения предлагает **+ New Table**.
Он открывает Modify Table в режиме создания: имя, колонки и остальные объекты
редактируются теми же формами, SQL preview показывает CREATE TABLE и связанные
команды. Apply/OK создаёт таблицу и обновляет дерево; Cancel отменяет черновик.
После Apply окно переходит к редактированию созданной таблицы. Существующая
таблица с таким именем не заменяется.

Правый клик на **таблице** предлагает Modify Table, Generate DDL to Clipboard
и Export Data to File. Редактор показывает дерево объектов слева, форму выбранного
объекта справа и SQL изменений снизу. Можно добавлять, копировать, удалять и менять
колонки, primary/unique/foreign keys, checks, индексы и триггеры. Первая строка дерева
открывает свойства таблицы; формы учитывают диалект: engine/collation/row format для
MySQL/MariaDB, owner/persistence/storage/tablespace/RLS для PostgreSQL,
STRICT/WITHOUT ROWID для SQLite. Доступны defaults, generated/identity columns,
параметры identity sequence, комментарии и явные grants. Apply выполняет показанный
SQL; устаревшие метаданные требуют Reload. Индексы ограничений редактируются через
соответствующие keys. Изменение структуры блокируется при несохранённых данных
таблицы. Ошибка MySQL DDL может оставить уже применённые команды; Reload перечитывает
фактическую структуру.

SQLite перестраивает таблицу транзакционно с сохранением данных, rowids,
AUTOINCREMENT и проверкой FK/зависимых views. Переименование выполняется отдельно
от изменений, требующих перестройки. Virtual tables требуют настроек своего модуля
и здесь не редактируются. PostgreSQL не позволяет менять порядок существующих
колонок; изменение partition/inheritance layout требует явного SQL. Удаление
зависимых объектов не выполняет CASCADE автоматически.

DDL и SQL/CSV export из меню таблицы ограничены выбранной таблицей. PostgreSQL также
включает её partitions в той же схеме, owned sequences и функции её триггеров;
внешние таблицы, типы и зависимости остаются внешними. Параметры и выбор файла
совпадают с экспортом схемы. Двойной клик сразу открывает вкладку: сначала видна
загрузка метаданных, затем данных. Вкладку можно закрыть во время загрузки;
поздний ответ не открывает её заново и не переключает фокус. После ошибки доступен Retry.

Экспорт встроен в приложение и **не требует pg_dump, mysqldump, интерпретатора
или компилятора**. SQL выгружает всю выбранную схему: INSERT и опциональный DDL.
MySQL/MariaDB использует SHOW CREATE для таблиц, views, routines, triggers/events;
PostgreSQL — системные каталоги для таблиц, partitions/inheritance, views/materialized
views, sequences, enum/domain/composite types, functions/procedures, keys/indexes,
triggers/rules/policies, owners/comments/ACL. SQLite сохраняет sqlite_master,
обычные таблицы, индексы, views, triggers и AUTOINCREMENT high-water marks.
Триггеры восстанавливаются после данных; generated columns вычисляются сервером.
Экспорт сохраняет видимые объекты схемы, а не общесерверные роли или внешние
зависимости других схем. Некоторые специальные PostgreSQL-объекты (пользовательские
base/range types, aggregates, operators/operator classes, text-search objects,
foreign tables), а также данные SQLite virtual tables пока возвращают явную
ошибку вместо неполного дампа; CSV видимых строк virtual tables доступен.

CSV выгружает выбранную таблицу: generated/computed columns, transpose,
column/row headers, delimiter и NULL marker. SQL/CSV preview показывает первые
64 KiB; файл содержит полный результат без лимита строк консоли. Update Preview
создаёт snapshot; Copy to Clipboard и Export to File используют тот же snapshot,
смена параметров требует новой генерации. Сохранение через стандартный диалог
выбора имени/папки атомарно заменяет файл после успешной генерации. Clipboard
ограничен 32 MiB, transpose — 16 MiB; обычный экспорт потоковый.

Run SQL Script открывает стандартный файловый диалог и выполняет UTF-8 SQL
в выбранной схеме (до 64 MiB, MySQL DELIMITER поддержан). SELECT-результаты
скрипта не удерживаются и не останавливают оставшиеся команды на лимите консоли.
SQLite исполняет скрипты в main; attached aliases принадлежат отдельной сессии.
Cancel прерывает работу; уже закоммиченные команды могут остаться применёнными.
Незавершённая явная SQLite-транзакция откатывается с сообщением об ошибке.

**Edit Connection…** открывает существующие поля подключения (имя, driver,
host/port, user/database, SSH и сохранение пароля). Save заменяет профиль,
сохраняя порядок и другие подключения; совпадение имени с другим профилем и
устаревшая форма возвращают ошибку. Пустой пароль сохраняет текущий сохранённый/
сессионный пароль при неизменном сервере. Для изменения сохранённого пароля или
сервера повторите Test Connection с новым паролем. Отмена не меняет JSON.
После Save подключитесь заново. Старые вкладки сохраняют правки и результаты,
но не выполняют запросы: для новых настроек откройте новую таблицу/консоль.


Профили находятся в `database_connections.json` рядом с `settings.toml` в каталоге
`.nozhik` текущего проекта. JSON содержит `name`, `driver` (`Postgres`/`Mysql`/`Sqlite`),
`host`, `port`, `user`, `database`, `ssh_profile_id` и `save_password`.
Сохранение атомарно; повреждённый JSON не перезаписывается. Пароли остаются
в памяти сессии. **Save password in system credential store** — явный opt-in
в Keychain / Windows Credential Manager / Linux Secret Service, доступный после
успешного теста именно этого профиля и пароля. Открытого пароля в JSON нет.

**Use SSH Tunnel** выбирает существующий SSH-профиль. Штатный SSH-flow проверяет
ключ хоста, при необходимости запрашивает доверие и пароль/ключ. После авторизации
создаётся отдельный loopback-туннель `127.0.0.1:0` к host/port БД; пул владеет
туннелем до отключения. SSH-профили и пароли БД независимы. SQLite работает локально.

Дерево показывает Online/Offline → схемы/базы → Tables/Views → таблицы →
**columns**, **keys**, **foreign keys**, **indexes** с количеством объектов,
типами колонок, PK, определениями ключей и ссылками на связанные таблицы.
При подключении загружаются только имена баз/схем и таблиц; колонки, ключи,
индексы и DDL запрашиваются при раскрытии/открытии конкретной таблицы.
Connecting… сменяется Online только после получения списка таблиц. Ошибки и
таймауты деталей относятся к одной таблице; Retry table metadata повторяет
загрузку. Отказ чтения keys/DDL не блокирует доступ к колонкам и данным.

Двойной клик или **Open Table (First 500 rows)** открывает таблицу в общей полосе
вкладок; повторное открытие возвращает к её текущим изменениям.
По умолчанию загружаются первые 500 строк. Панель снизу показывает диапазон,
переход к первой/предыдущей/следующей странице и размер страницы 100/500/1000/5000.
Запрос получает одну дополнительную строку для определения следующей страницы:
`of 501+` означает нижнюю оценку, без полного COUNT большой таблицы. Без явного
ORDER BY порядок зависит от сервера. Изменения
таблицы другими клиентами между запросами могут сдвинуть страницы.
Переходы и смена размера доступны после Submit/Revert и завершения загрузки.
Над таблицей доступны WHERE (например, `id < 1000`) и ORDER BY (например,
`name ASC, id DESC`), без повторного ввода этих ключевых слов. Enter или Apply
применяет оба поля и возвращает на первую страницу. Крестик очищает поле
и сразу применяет оставшиеся условия. Фильтрация и сортировка выполняются
сервером до LIMIT, сохраняются при пагинации, Reload и Submit.
Стрелка каждого заголовка циклически переключает без сортировки → ASC → DESC →
без сортировки и синхронизирует ORDER BY. Нейтральная иконка — два треугольника,
ASC — вверх, DESC — вниз. Стрелка заменяет ручной ORDER BY сортировкой одной
колонки; сложные ручные выражения оставляют нейтральные иконки. Скрытого ORDER BY
по первичному ключу нет. При ошибке запроса прежние данные и применённые условия
сохраняются; введённый текст остаётся для исправления. Условия и стрелки
заблокированы до Submit/Revert правок и завершения загрузки.
Поля принимают выражения одного SELECT: комментарии, разделители statements
и дополнительные внешние SQL clauses отклоняются. В строках используйте
удвоенные SQL-кавычки вместо обратного слеша.
MySQL/MariaDB GEOMETRY читается как бинарное пространственное значение; POINT
показывается как `POINT (x y)`. Остальные формы показываются в hex. Пространственные
ячейки доступны для чтения; редактирование других колонок сохраняет исходные
координаты и SRID.
Временные значения MySQL/MariaDB (`TIMESTAMP`, `DATETIME`, `DATE`, `TIME`)
отображаются как возвращены сервером: сохраняются доли секунды, нулевые даты
и интервалы TIME вне диапазона обычного времени суток. SQL NULL остаётся NULL.
**New SQL Console** создаёт вкладку с Rope-редактором и SQL-подсветкой.

Ячейки таблицы редактируются локально. **Add Row** добавляет строку с DEFAULT,
**Delete Rows** помечает выбранные строки на удаление. Клик по номеру выделяет
строку, Cmd/Ctrl добавляет или убирает строку из выделения, Shift выбирает диапазон.
Контекстное меню ячейки задаёт SQL NULL; в новой строке также доступен DEFAULT.
**Revert** отменяет все неотправленные изменения. **Preview Pending Changes**
показывает SQL пакета, **Submit** выполняет этот же пакет в транзакции и обновляет
данные. Эти три кнопки активны при наличии изменений. До Submit записей в БД нет.
Исходные значения входят в WHERE, изменение первичного ключа использует старое
значение. Если строка уже изменилась или соответствует нескольким строкам,
пакет откатывается с ошибкой; локальные изменения сохраняются для исправления.
MySQL Submit требует InnoDB. Представления доступны для чтения.
**Reload Page** перечитывает данные (сначала завершите правки через Submit/Revert),
**Cancel Running Statements** отменяет выполняющийся запрос. После начала COMMIT
приложение дожидается его результата. **Go to DDL** открывает SQL-текст определения
таблицы в отдельной вкладке редактора; файл можно сохранить на диск.
При закрытии таблицы с правками доступны Discard/Cancel; Save All не отправляет SQL.

Для SQL-консоли:
Выберите соединение и схему, нажмите **▶ Execute** или **Ctrl/Cmd+Enter**.
Выполняется выделенный SQL либо выражение под курсором; Ctrl/Cmd+A позволяет
выполнить весь скрипт. Кавычки, dollar-quoted строки и комментарии защищают
вложенные `;` при выборе выражения. Схема применяется на том же SQL-соединении,
что и запрос (PostgreSQL search_path / MySQL USE); для SQLite используйте
квалифицированные `schema.table` имена, как в генерируемом preview.

В SQL-редакторе автоматически появляются подсказки таблиц и полей из схемы БД;
Ctrl+Space вызывает список явно, стрелки выбирают вариант, Tab/Enter вставляют
цитированное имя. Поля берутся из таблиц FROM/JOIN/UPDATE/INTO, поддерживаются
псевдонимы (`g.`). Колонки подгружаются в фоне без предварительного раскрытия
таблиц в дереве. Строковые литералы и комментарии не вызывают подсказок.

Каждый набор результатов получает свою вкладку внизу консоли с тем же редактором
таблиц, но без формы WHERE / ORDER BY и постраничной подгрузки. Прямой SELECT
из одной базовой таблицы поддерживает правки ячеек, Add/Delete Row, Revert,
Preview и транзакционный Submit. Можно выбирать часть колонок, если в выборку
входит весь первичный ключ. Полная выборка без PK использует проверку ровно одной
затронутой строки, как основная таблица. JOIN, агрегаты, вычисления, переименованные
колонки, views, CTE и наборы из нескольких statements доступны для чтения.
Стрелки заголовков сортируют только загруженный результат.

Новая строка получает значения из однозначных равенств WHERE: `type=11` заполнит
`type` значением 11, в том числе если поле отсутствует в SELECT. Поддерживаются
литералы чисел, строк и boolean, AND, скобки и квалификация псевдонимом. Неравенства,
выражения, OR/NOT и конфликтующие равенства не дают предполагаемых значений.
Остальные поля сохраняют DEFAULT. Reload и Submit повторяют исходный выполненный
SQL, даже если текст редактора уже изменён. До Submit/Revert нельзя заменить
результат новым запросом или сменой подключения; закрытие предупреждает о правках.

Выдача ограничена 10 000 строками / 16 МиБ сохранённых значений с пометкой
result limit. Нижняя часть показывает число строк, elapsed ms и affected rows.
**Cancel** отменяет ожидание запроса; уже закоммиченные изменения могут остаться.
Отдельные постоянные SQL-сессии/транзакции на вкладку и SQL LSP не входят
в эту версию. Транзакционный скрипт выполняйте одним запуском. SQLite JSON остаётся
Text, поскольку движок хранит его как TEXT; нативные PostgreSQL/MySQL JSON
возвращаются как Json. Неподдержанные vendor-типы дают ошибку декодирования.


## RC1: глобальное меню и единый интерфейс

File, Edit, View, Navigate, Code, Git, Database, Terminal, Tools и Help вызывают
зарегистрированные действия ActionRegistry. macOS использует нативное меню
AppKit через muda; Windows/Linux — встроенную строку меню egui. Подписи сочетаний

File → Open File / Folder принимает абсолютный путь; New File создаёт новый

Общие семантические цвета, подсветка, методы HTTP, ANSI base palette, радиусы

Database, нижнего терминала и разделитель SQL editor/results.
Пропорции сохраняются фоновым worker в `layout.json` рядом с `settings.toml`
и восстанавливаются при запуске. Повреждённый файл сохраняется без перезаписи.

При выходе оркестратор останавливает LSP (shutdown → exit), PTY/ConPTY,
SQL-пулы через Pool::close, SSH-сессии и туннели, затем основной Tokio runtime.
Каждый шаг ожидания ограничен по времени; аварийный kill процесса не даёт
такой гарантии. Help → About Nozhik показывает версию приложения, базовый Git commit сборки,
версию rustc, ОС/архитектуру, egui/Glow и Tokio.

Для отдельной конфигурации, например при проверке релиза:

```sh
cargo run -p app -- --config /absolute/test/settings.toml /absolute/test/project
```

Для изоляции параметров самого проекта используйте
`/absolute/test/project/.nozhik/settings.toml`; `--config` задаёт настройки
стартового окна и расположение общего списка недавних проектов.

## Code Styles и Reformat Code

**Code → Reformat Code** (`Ctrl/Cmd+Alt+L`) форматирует выделение либо весь
файловый буфер одной отменяемой транзакцией. Приоритет имеет активный PHP LSP
с поддержкой formatting/rangeFormatting; при отсутствии поддержки, null, пустом
или фактически неизменяющем текст ответе и ошибке запроса используется локальный
Tree-sitter formatter. Ответы для изменённого
буфера, закрытой вкладки или сменившегося профиля отбрасываются.

Встроенный `crates/config/code_styles/php/php_psr12.json` задаёт PSR-12 профиль.
Дополнительные JSON сканируются в `~/.nozhik/code_styles/<extension>/` и
`code_styles/<extension>/` рядом с `settings.toml`; последний каталог имеет
приоритет при совпадении имени файла. Settings → File Types & Code Styles
позволяет выбрать профиль или **None**, палитру Default/Muted/Plain Text и
перечитать каталог. Выбор сохраняется в settings; повреждённые профили сообщают
ошибку и не перезаписываются. Неизвестный/удалённый профиль отключает форматирование.
PHP/PHTML по умолчанию используют встроенный профиль, остальные расширения — None.

Smart Paste при выбранном профиле выравнивает одну или несколько строк по строке
вставки. Ведущий отступ под кареткой заменяется целиком, поэтому пробелы не
удваиваются. Лёгкий лексический проход по PHP-фрагменту восстанавливает вложенность
по структурным скобкам, игнорируя скобки внутри строк и комментариев. Multiline
literals и heredoc вставляются дословно; окончания строк сохраняются.
С None вставка остаётся дословной. Локальный PHP formatter меняет только whitespace
между AST-токенами и проверяет сохранность дерева повторным разбором. Это
реализация правил JSON-профиля, а не полный PSR-12 validator. Heredoc/nowdoc,
строковые литералы и HTML вне PHP-тегов сохраняются байт-в-байт, а окружающий
PHP-код форматируется. Если LSP меняет эти текстовые блоки, используется локальный
форматтер. Синтаксически повреждённый PHP по-прежнему сообщает ошибку.
Tree-sitter отдельно от LSP выдаёт ошибки ERROR/MISSING, маркеры незакрытых
скобок и подсказки. Settings → General содержит шрифт, размер, plain-text tab width
и имеющуюся тему New UI Dark.

Редактор: LMB ставит каретку, drag выделяет текст без панорамирования холста,
Shift+click расширяет выделение, double click выбирает идентификатор (включая
Unicode), triple click — строку с окончанием. Колесо прокручивает viewport по
обеим осям, сохраняя каретку и выделение. Reformat Code поддерживает также
PHP-фрагменты без открывающего тега; выбранный вызов метода получает отступ
на основе полного AST, без изменения соседних строк.

При активном Code Style Enter сохраняет отступ текущей строки и добавляет шаг
после открытой структурной скобки. Например, после `    if (!$condition) {`
каретка оказывается на новой строке после 8 пробелов. Перенос и отступ отменяются
одним Undo; без профиля Enter вставляет только окончание строки. Reformat Code
дополнительно проверяет структурные отступы после непустого ответа PHP LSP:
частичные правки сервера не оставляют `print('test');` на нулевой колонке внутри if.

## Офлайн-справочник PHP

Подсказки стандартной библиотеки работают без PHP и LSP. Встроены 11 каталогов
PHP 7.0–7.4 и 8.0–8.5, сформированных Reflection из официальных CLI-образов PHP.
Каждый содержит примерно 2 700–3 400 функций, классов, интерфейсов, глобальных
констант и ключевых слов плюс методы и константы классов. Файлы находятся в
`crates/language_support/data/php_<version>.json`; `catalog-manifest.json`
фиксирует patch-версию PHP, digest образа, расширения, счётчики и SHA-256.
Объём всех JSON — около 31 МиБ.
Глобальный **PHP Language Level**: Settings → File Types & Code Styles → PHP
(также PHTML), версии 7.0–7.4 и 8.0–8.5, по умолчанию 8.5. Выбор сохраняется.
Каталог версий: `~/.nozhik/languages/php/versions/php_<version>.json`.
Пользовательский JSON имеет приоритет; при его отсутствии IDE использует
встроенный каталог того же уровня. Поле Offline catalog показывает фактически
загруженную версию. Повреждённый пользовательский файл сообщает ошибку и сохраняет
предыдущую базу. Устанавливать Docker или PHP для подсказок не нужно.

Попап открывается с первого символа или по **Ctrl+Space**. Up/Down перемещают
выбор, наведение и одиночный клик выбирают строку, Enter/Tab или двойной клик
вставляют вариант. Функции получают `()` с кареткой внутри; Esc/клик снаружи
закрывают список. Поиск поддерживает глобальные имена и явный `Class::member`.
LSP добавляет проектные символы; определение типа экземпляра остаётся за LSP.

Повторная генерация всех встроенных версий (последовательно, один контейнер за раз):

```sh
python3 scripts/generate-php-catalogs.py
# Можно обновить только одну версию:
python3 scripts/generate-php-catalogs.py --version 8.5
```

Скрипт использует `php:<version>-cli-alpine` для Linux/amd64, удаляет каждый
контейнер перед следующей версией и по умолчанию удаляет скачанные им образы.
Предсуществовавшие образы сохраняются. Общая очистка Docker не выполняется.
Точный Docker executable можно передать через `--docker`; `--keep-images`
сохраняет скачанные образы. Каталоги содержат сущности всех расширений, включённых
в эти образы. Опциональные расширения, например intl/gd/mysqli, требуют генерации
из своего PHP-окружения с установленными расширениями:

```sh
php scripts/generate_php_stubs.php --output=php_8.5.json
# Или из выбранного Docker-образа; для полного набора расширений используйте свой образ:
docker run --rm -v "$PWD:/work" -w /work php:8.5-cli \
  php scripts/generate_php_stubs.php --output=php_8.5.json
cargo run -p nozhik-language-support --example validate_php_stubs -- php_8.5.json
mkdir -p ~/.nozhik/languages/php/versions
cp php_8.5.json ~/.nozhik/languages/php/versions/
```

После установки базы перезапустите IDE либо переключите уровень на другой и
обратно. Скрипт совместим с PHP 7.0+ и не запускает найденные функции/методы.
Reflection обычно не предоставляет краткую документацию встроенных сущностей;
такие поля остаются пустыми. Типы, отсутствующие в старом runtime, записываются
как mixed. Для PHP 8.1+ учитываются также
[tentative return types](https://www.php.net/manual/en/reflectionfunctionabstract.gettentativereturntype.php).
Значения платформенных констант полной базы соответствуют ОС контейнера.

## AI Inline Completion (Ollama)

Локальные FIM-подсказки появляются серым текстом у каретки после паузы ввода
1000 мс. Tab вставляет всю подсказку одной операцией Undo; Esc, новый ввод,
навигация, клик, потеря фокуса и смена документа отменяют подсказку и запрос.
Многострочные подсказки временно сдвигают суффикс и следующие строки только
на экране, не изменяя буфер до принятия. Обычный PHP/LSP popup продолжает
работать; при видимом ghost text Tab принимает именно его.

В **Settings → AI Assistant (Ollama)** доступны состояние сервиса, имя модели,
кнопка **Download Model**, прогресс текущего слоя в MB/процентах, включение
подсказок и задержка. Установите [Ollama](https://ollama.com); Nozhik запускает сервис автоматически
при включённом AI и заранее загружает уже скачанную выбранную модель.
IDE обращается к `http://127.0.0.1:11434`. Модель по умолчанию —
`qwen2.5-coder:1.5b-base`; скачивание начинается только по нажатию кнопки.
При закрытии Nozhik модель выгружается из RAM/VRAM; запущенный самим Nozhik
сервис завершается вместе с дочерними процессами. Ранее запущенный внешний
сервис остаётся работать. Отключение AI также освобождает ресурсы; смена модели
выгружает предыдущую. Автостарта при выключенном AI нет. Проверку состояния
можно повторить кнопкой **Refresh service status**. Ошибки генерации кратко
показываются в строке состояния; ошибки скачивания видны в настройках.

Настройки сохраняются стандартным worker: `ai_enabled = true`,
`ai_model = "qwen2.5-coder:1.5b-base"`, `ai_debounce_ms = 1000` (50–5000 мс).
Контекст ограничен 2000 Unicode-символами до каретки и 1000 после неё;
raw FIM generation допускает до 60 секунд на холодную загрузку модели и имеет
лимит 64 токена ответа. Подсказка запрашивается после открытия файла,
возврата фокуса, остановки каретки и паузы ввода — печатать для запуска не нужно.
Нужен один курсор без выделения. Esc скрывает подсказку до изменения позиции,
документа или фокуса; бесконечных повторных запросов при простое нет.

В строке состояния видны «AI: generating…», готовность подсказки, отсутствие
предложения или причина ошибки, включая необходимость скачать модель.
Установка приложения Ollama сама по себе не устанавливает модель: скачайте
выбранную модель кнопкой Download Model. После временного отказа сервиса есть
два ограниченных повтора с задержкой; новый ввод отменяет устаревшую генерацию.

## Контекстная документация стандартной библиотеки

**Cmd+Hover** на macOS / **Ctrl+Hover** на Windows и Linux подчёркивает известный
символ активного PHP-каталога и показывает Darcula-попап: тип, имя, сигнатуру,
имеющееся описание и подсказку перехода. **Cmd/Ctrl+Click** открывает документацию
в системном браузере в фоне, сохраняя каретку и выделение. Поддерживаются функции,
классы, интерфейсы, глобальные константы и явные `Class::method` / `Class::CONSTANT`.
Тип экземпляра и проектные определения по-прежнему обслуживает LSP; локальный
индекс определений в этой итерации не добавлен. Обычный LSP hover и F12 сохраняются.

URL задаются в `crates/language_support/data/php_doc_rules.json`; по умолчанию
используется универсальный алиас `https://www.php.net/{name}`. Пользовательский
`~/.nozhik/languages/php/doc_rules.json` заменяет встроенные правила при следующей
загрузке каталога (перезапуск или смена PHP Language Level и обратно). Например:

```json
{
  "language_id": "php",
  "label": "php.net",
  "rules": {
    "function": {
      "template": "https://www.php.net/manual/ru/function.{name}.php",
      "lowercase": true,
      "underscores_to_hyphens": true
    },
    "class": {
      "template": "https://www.php.net/manual/ru/class.{name}.php",
      "lowercase": true
    }
  },
  "fallback": { "template": "https://www.php.net/{name}" }
}
```

Fallback применяется при отсутствии правила категории; сетевых запросов для
проверки страницы нет. Шаблоны требуют HTTPS и `{name}`. Некорректный файл правил
сообщает ошибку загрузки и сохраняет предыдущий каталог, исходный файл не меняется.
Пустое описание в Reflection-каталоге не дополняется выдуманным текстом.
Попап использует встроенный JetBrains Mono с лицензией SIL OFL 1.1.

### Удаление пустых строк и лишнего отступа

На строке, содержащей только пробелы/табы, обычные **Backspace** и **Delete**
сначала удаляют лишний отступ слева от каретки до расчётной позиции. Если каретка
уже на этой позиции или левее, строка удаляется целиком, а каретка переходит
в конец предыдущей строки. При удалении первой строки — в начало следующей.
Расчёт использует предыдущую непустую строку и правила отступа Enter активного
Code Style; без профиля сохраняет отступ предыдущей непустой строки. Табы
учитываются по табуляционным позициям; при необходимости часть таба заменяется
пробелами для точного попадания в колонку. Выделенный текст удаляется как обычно.
Каждое нажатие — отдельный шаг Undo, включая восстановление кареток.

## Локальный индекс символов проекта

Preview использований ограничен 512 байтами вокруг символа; исходные координаты
для переходов сохраняются полностью. Неизменённые данные индексов и preview
разделяются между worker и интерфейсом. В очередях хранятся последние правки
каждого файла и последние снимки; поток файловых событий объединяется в сверку
с диском. Индексация поддерживаемых файлов и несохранённых правок сохраняется.
Кэши схемы 6 строятся заново; прежние index_php.json/index_css.json не загружаются
и удаляются только после успешного сохранения нового кэша соответствующего языка.

PHP-файлы проекта индексируются через Tree-sitter на отдельном worker, без LSP.
Кэш `.nozhik/cache/index_php_v6.json` загружается при открытии проекта; сверка mtime
и размера повторно разбирает только изменённые файлы. Watcher и успешное сохранение
обновляют один путь; несохранённые буферы накладываются на дисковый индекс и не
попадают в кэш. Все поддерживаемые файлы внутри проекта, включая `vendor`,
`node_modules`, `target` и пути из `.gitignore`/`.ignore`, индексируются наравне
с остальным кодом. Исключены только внутренние каталоги `.git` и `.nozhik`;
символические ссылки не обходятся. Composer-настройка для этого не нужна.

**File → Invalidate Caches / Delete Caches…** запрашивает подтверждение и удаляет
`.nozhik/cache` перед фоновым перестроением. Прогресс виден справа в status bar.
Действие зарегистрировано как `file.invalidate_caches`.

Completion объединяет локальные переменные/параметры, символы проекта и PHP-каталог.
`->` показывает доступные нестатические члены определённого класса, `::` —
статические члены и константы; `.` не запускает member completion.
Поддерживаются `$this`, типизированные параметры и `$car = new MyCar()` в текущей
области видимости, namespace и простые `use … as …`. Триггеры задаются структурой
LanguageTriggerConfig. `$this->` сразу предлагает собственные члены класса, доступные
public/protected члены родителей и члены подключённых (в том числе вложенных) трейтов.
Собственные private-члены и private-члены своих трейтов также доступны внутри класса.
Список подстраивается под содержимое: до девяти компактных строк с прокруткой,
ширина до 440 пунктов. Cmd/Ctrl+Hover показывает исходную сигнатуру и документацию,
Cmd/Ctrl+Click и F12 переходят к локальному объявлению. Alt+F7, Code → Find Usages
и счётчик над классом/методом открывают список использований: фильтр, группировка
по файлам, стрелки, Enter/клик для перехода, Esc и отдельное окно через ↗.
Неиспользуемые методы/свойства и приватные константы приглушаются; это вывод
статического индекса, без знания вызовов через Reflection/framework conventions.

LanguageId изолирует PHP, Go и JavaScript/TypeScript; извлечение символов пока
реализовано для PHP. Это ограниченный статический PHP resolver: динамические
имена, trait adaptations, union/intersection types,
цепочки возвращаемых объектов и межпроцедурный data flow пока требуют LSP.
Строки и комментарии не считаются текстовыми вызовами методов. Нативный вид
отдельного окна использований требует проверки на целевой ОС.

Использования PHP-классов учитывают `use` (в том числе групповой и `as`),
`extends`, `implements`, type hints, `new`, `instanceof`, attributes/catch и имя
класса в статических обращениях. Вызовы унаследованных методов и свойств ведут
к фактическому объявлению; переопределения и `parent::` разрешаются отдельно.
При Cmd/Ctrl-наведении на **объявление** открывается интерактивный список его
использований. Он остаётся открыт после отпускания модификатора: клик по строке
открывает файл вызова и прокручивает к нему; Cmd/Ctrl+Click по вызову возвращает
к объявлению. Изменение родителя/переопределения пересвязывает готовые ссылки,
не перепарсивая вызывающие файлы. Кэш старой схемы автоматически перестраивается
один раз. Готовый пример с точными ожидаемыми счётчиками:
[examples/php-symbol-navigation](examples/php-symbol-navigation/README.md).

## Включённые языки и индексация

**Settings → Languages** позволяет включать и отключать языковые службы без
перезапуска. Сейчас реализован PHP (`.php`, `.phtml`, без учёта регистра).
JavaScript/TypeScript, HTML, YAML и Go показаны как Coming soon; их службы ещё не
реализованы. Когда добавляется обработчик языка, его регистрация становится
доступной в этом списке. Старые настройки сохраняют включённый PHP по умолчанию;
можно отключить все языки.

Отключение языка останавливает индексатор/LSP, убирает подсветку, diagnostics,
completion, навигацию по символам и языковое форматирование. Файл остаётся
доступен для обычного редактирования и поиска по имени. Дисковый кэш сохраняется:
при повторном включении проверяются mtime/size и разбираются только изменения.
Выбор сохраняется в settings.toml/settings.json, например `enabled_languages = []`
отключает языковые службы, `["php"]` включает PHP.

Семантический индекс читает содержимое только поддерживаемых включённых типов.
Обход каталогов нужен, чтобы найти эти файлы; отдельный лёгкий индекс путей для
Go to File содержит имена всех файлов, кроме внутренних `.git`/`.nozhik`, без разбора их содержимого.
HTML/JSON/картинки не попадают в PHP-индекс. Их изменения и неизменившиеся PHP-файлы
не вызывают перезапись кэша или отправку нового полного снимка индекса.
Первичный разбор собирает факты пакетом, затем один раз связывает декларации и
ссылки; поиск декларации по FQN использует хеш-таблицу. Обычная правка по-прежнему
разбирает только изменённый PHP-файл.

Индекс учитывает ссылки на классы в `use`, объявлениях типов, `new` и типах
PHPDoc (`@var`, `@param`, `@return`, `@throws`, `@extends`, `@implements`).
Cmd/Ctrl+Click по импорту ведёт к объявлению, включая игнорируемые файлы
в `vendor`; список использований класса содержит обратную ссылку на импорт.
Поддерживаются constructor property promotion, цепочки типизированных свойств
(в том числе унаследованных), объявленные возвращаемые типы методов/функций и
`(new Class())->method()`. Кэш схемы 3 автоматически перестраивается один раз
после обновления; открытые несохранённые буферы сохраняют свои связи при очистке.

Терминал: вкладки оформлены как вкладки файлов; `+` создаёт сессию, `⋮ → Close All`
завершает все сессии, `−` скрывает панель с сохранением работающих процессов.
При открытии пустой панели автоматически создаётся локальный шелл. Начальная
высота — 40% окна; после перетаскивания границы выбранная высота сохраняется
при скрытии и повторном открытии. Выделение мышью/Shift-кликом и контекстное меню
поддерживают Copy/Cut/Paste для активного терминала, включая системный буфер и
bracketed paste. Вырезание удаляет текст в текущей строке ввода шелла; история
вывода, многострочное выделение и TUI-экран доступны для копирования.

В Git → Changes контекстное меню файла содержит **Ignore Folder (Add to .gitignore)**
сразу после игнора выбранных файлов. Клик по названию добавляет ближайшую папку,
стрелка открывает список её предков до корня репозитория (без самого корня).
Для файла в корне действие недоступно. Правило `/path/to/folder/` записывается
в корневой `.gitignore`; уже отслеживаемые файлы остаются отслеживаемыми.

Над Summary/Description в Git → Changes доступна **Auto-fill Commit Message**.
Кнопка активна при включённом AI completion, выбранной модели и хотя бы одном
staged-файле. По нажатию выбранная локальная Ollama-модель составляет английские
Summary/Description по HEAD→index diff, без unstaged/несохранённых изменений.
Запрос выполняется в фоне, доступен Cancel; поля остаются редактируемыми,
коммит создаётся отдельно обычной кнопкой. Изменение полей, AI-настроек, проекта
или Git mutation отменяет запрос; внешнее изменение index/HEAD обнаруживается
повторной проверкой перед заполнением. Ошибки сохраняют прежний текст.
Большие diff ограничены 24 KiB с явным маркером для модели; бинарные файлы
передаются как Git metadata. Модель не скачивается автоматически.

## Git в настройках проекта

**Settings → Git** доступен для любого открытого Git-репозитория, включая папки,
ранее клонированные GitHub Desktop или другим клиентом. Показывает корень repo,
origin fetch URL, необязательный отдельный push URL, имя/email автора коммитов,
метод аутентификации и credential helper. Способы входа общие с Clone Repository:
Public / system credentials, HTTPS Token, Login / password, SSH key/passphrase.
GitHub требует token вместо пароля аккаунта.

**Save Git Settings** меняет только локальный Git config этого репозитория,
с проверкой внешних изменений и атомарной записью через config.lock. Пустой push URL
использует fetch URL. Имя/email и helper при пустом значении используют системные
настройки. **Reload Git Settings** перечитывает конфигурацию, сбрасывая черновик.
**Test Fetch Connection** проверяет URL/аутентификацию без сохранения полей и без
обновления refs; изменения credential helper сначала нужно сохранить. Проверка
не подтверждает права на push — они проверяются при самом push.

Fetch/Pull/Push используют credentials выбранного проекта и его локальные Git
credential helpers. Токены, пароли и passphrase остаются в памяти до закрытия
проекта. Пустые секретные поля сохраняют существующие session credentials только
для прежних URL и метода входа; смена адреса или метода требует соответствующих
credentials. Ошибки авторизации направляют в Settings → Git, отсутствие имени/email
автора — туда же. Изменение origin не выполняет Fetch/Push автоматически и сохраняет
существующие refs: после смены репозитория выполните Fetch для их актуализации.

Git transport errors теперь различают HTTP 401/403/404, proxy/rate limit/server
errors, TLS/SSH trust и сетевые сбои, не печатая response body, URL или credentials.
Для GitHub HTTP 403 показана подсказка проверить Resource owner, доступ токена
к конкретному репозиторию и Contents permissions: read для Fetch, read and write
для Push; при необходимости — одобрение организации. HTTP 404 может означать
недоступный private repository. Пустой токен требует повторного ввода для текущей
сессии; случайные пробелы/перевод строки по краям токена убираются перед отправкой.
